# StreamSage Service Secrets — Pre-Provisioning Guide

All secrets must be created in the target namespace **before** ArgoCD syncs the service
Applications. Secrets are **never committed to Git** — they are managed externally.

## Recommended Secret Management

For production: use **External Secrets Operator** (ESO) + IBM Secrets Manager or HashiCorp Vault.
For dev/test: create secrets manually with `oc create secret generic ...`

---

## Secret Reference by Service

### `api-gateway-secrets` (namespace: `streamsage-{env}`)

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: api-gateway-secrets
  namespace: streamsage-dev   # change per environment
type: Opaque
stringData:
  DATABASE_URL: "postgresql://streamsage:PASSWORD@postgres-cluster-rw.postgres-dev.svc:5432/streamsage"
  REDIS_URL: "redis://:PASSWORD@redis.streamsage-dev.svc:6379"
  JWT_SECRET_KEY: "<random 32-byte secret>"
```

## How to Obtain the Kafka SCRAM Password

The IBM Event Streams operator generates a Kubernetes Secret for each KafkaUser CRD.
For `kc-user` in namespace `kafka-dev`:

```bash
oc get secret kc-user -n kafka-dev -o jsonpath='{.data.password}' | base64 -d
```

Use the decoded value as `KAFKA_PASSWORD`.

## SSL/TLS (CA certificate)

Event Streams presents a self-signed CA. Mount it as a ConfigMap and set `KAFKA_SSL_CA_LOCATION`:

```bash
oc get secret kafka-es-cluster-ca-cert -n kafka-dev \
  -o jsonpath='{.data.ca\.crt}' | base64 -d > /tmp/ca.crt
```

Add to the service pod via an init container or a Volume/VolumeMount that copies it to `/etc/kafka-ssl/ca.crt`,
then set `KAFKA_SSL_CA_LOCATION=/etc/kafka-ssl/ca.crt` in the ConfigMap.
